# Vayora Social Studio

Vayora's internal team web app, built with **Next.js 16 App Router + React 19**. Active location: `E:\Work\VAYORA\Vayora-SocialStudio`. Team login and database storage are fully functional. The initial library contains 24 original concepts: 10 Reels, 8 image posts, and 6 carousels.

The interface is in English by default, with an ID/EN language switch (Indonesian is available as a translation). Content generated by the app (captions, titles, blog articles) is written in Indonesian, following the Vayora brand voice.

## Getting started and testing login

1. Run `Mulai-Vayora.cmd` in this folder.
2. Open http://localhost:3210.
3. Log in with a team account that was migrated from the previous project. There is no need to create a new account.
4. Try signing out, then signing in again with the same account.

There is no default username or password. Email is used as the local login identity; no email is sent automatically.

## Requirements

- Node.js 24 or later.
- FFmpeg and ffprobe available on PATH, for reading video and preparing Reels.
- Dependencies are already installed on this machine. For a fresh install, run `npm ci` followed by `npm run build`.

Alternative local command: `npm run start:local` after `npm run build`. For development use `npm run dev`. To re-import starter content that is not yet present: `npm run seed`. The import does not overwrite IDs that are already stored.

## Usage flow

For the team: open **Home** to see the 7-day schedule, content that needs review, connection status, and problem alerts (content that failed or whose publish status is uncertain, Instagram/YouTube connections that are disconnected or about to expire, schedules that will not publish). Click **Create post** (form on the left, Instagram/YouTube Shorts preview on the right; files can be dragged and dropped), then follow four steps: choose Instagram or YouTube Shorts → upload a photo/video (the content type is chosen automatically: Photo, Carousel, Reel, or Short) → write the title and caption → submit for review, schedule (the approval checkbox is required), or save as a draft. Content codes (I01, S01, …) are generated automatically. If a Gemini key has been entered in **AI settings**, the title and caption are written by AI right after the media is uploaded (`POST /api/assistant/draft` with `{platform, mediaIds}`); the team only needs to review and edit them, or press **Rewrite with AI**.

Full flow: Library → open the detail summary → choose Edit content → check the media and caption → give approval → mark as ready to publish or save a schedule. Changes to the material require a new approval. All publishing dates use WIB.

The schedule is shown directly on the library cards. The Post button now opens a check before manual publishing; the Instagram account and live publishing must be ready. That content's previous schedule is replaced, while other queue items are not resumed. The queue can be paused and schedules can be cancelled. Published content can only be copied. Results with an uncertain status are locked until the status is checked with Meta, to prevent duplicate uploads.

**Delete content** is in the Detail dialog. Scheduled content has its schedule cancelled as well; content that is being processed or whose result is uncertain cannot be deleted; published content can only be deleted by the owner, and the Instagram post remains. Deleted content disappears from the library, calendar, and queue, but its history is kept and its ID is not reused. API: `DELETE /api/posts/:id?revision=N` (session + `x-csrf-token` header).

## Import content (one entry point for bulk upload)

The **Import content** menu (owner only) reads a single folder or several files at once, including subfolders, for example the whole `Short YT` folder. Drag and drop folders/files onto the page, or use the **Choose folder** / **Choose files** buttons; when a folder is dropped, folders such as `node_modules` are not opened at all, which makes it faster.

- **Videos and photos** (MP4, JPG, PNG, WebP) are matched in this order: file name mentioned in the text → content code in the file name (`V01-…`, `I01-…`, `C01-slide-1…`, `S01-…`) → number in the file name (`Vayora-Shorts-03.mp4` → episode 03) → episode folder (`03 - Title/Video/…`). Files nested more than two folders below the episode folder (project assets, references) and folders such as `node_modules` are ignored. If there are two versions of a video for one episode, choose the version in the table. Images named `Cover…` are used as the Instagram Reel cover.
- **Recognized text formats** (the importer accepts Indonesian names, and also English aliases):
  - JSON/CSV packages, with one row or object per episode:

    | Indonesian name | English alias |
    | --- | --- |
    | `episode` / `id` | `episode` / `id` |
    | `judul` | `title` |
    | `deskripsi_lengkap` / `caption` | `description` / `caption` |
    | `tags_opsional` | `tags` |
    | `file_video` | `video_file` |
    | `platform`, `tanggal`, `jam` | `platform`, `date`, `time` |

  - .txt files, one per episode or combined (`EPISODE 01 — …`), with the sections below:

    | Indonesian section | English alias |
    | --- | --- |
    | `JUDUL` | `TITLE` |
    | `DESKRIPSI LENGKAP` | `FULL DESCRIPTION` |
    | `TAGS` | `TAGS` |

  - Markdown caption lists (`## V01 … Caption:`).
  - Blog articles in `.md` use a metadata table (`Metadata SEO` or `SEO metadata`) and the body section (`Naskah artikel` or `Article body`).

  If several files describe the same episode, JSON is used first, then CSV, .txt, and Markdown only fill in the parts that are still empty.
- **Media without text** that is named with a content code becomes its own content item with a title taken from the file name; save it as a draft if there is no caption yet. Codes from files are kept if they are not yet in use; codes that already exist in the library are not imported again.
- S codes are always YouTube Shorts; V, I, and C are always Instagram. Otherwise the platform follows the `platform` column or the **Default platform** option.

Then set the schedule (start date, days, and WIB times; slots that are already taken are skipped, and the date and title can be changed per row), tick the approval checkbox, and run. Each row is uploaded and then scheduled, submitted, or saved as a draft one at a time; rows that fail show the reason without stopping the others.

Tags are sent to the YouTube Tags field. If the description mentions AI-generated visuals, the "synthetic content" option is ticked automatically and YouTube receives `containsSyntheticMedia`. Pinned comments must still be pinned in YouTube Studio. Until the Google project passes the audit, videos remain private. Images are converted to sRGB JPEG; videos are prepared with faststart and 128 kbps AAC audio; the original production files are not changed. The old addresses `/import` and `/package` open the same page.

## Team account

The owner opens **Team account** to see all members (name, email, role, join date) and invitations that have not been used yet. **Delete** ends that member's sessions immediately and revokes their access; content they created stays and is recorded in History. The owner cannot delete their own account or the last owner. **Cancel** revokes an invitation link before it is used. API (owner only): `GET /api/team`, `DELETE /api/team/:id`, `DELETE /api/team/invites/:id`.

## Blog to Sanity.io

The **Blog** menu writes, schedules, and publishes articles to a Sanity dataset (`post` schema: title, slug, excerpt, Portable Text body, mainImage + alt, publishedAt, seoTitle, seoDescription, author, categories). The owner enters the Project ID, dataset, and Editor token in **Connections & publishing → Blog · Sanity.io** (the token is encrypted and never shown again), then presses **Check connection** to read the existing article fields, authors, and categories. Article content is written in Markdown and converted to Portable Text (h2/h3 headings, lists, quotes, bold, italic, links; tables are flattened into bullet points). Documents use a fixed _id (`vayora-B01`), so re-sending replaces the document instead of duplicating it. Scheduled articles are published by the same scheduler as Instagram/YouTube and follow the live publishing switch and the queue pause. **Import content** reads `.md` articles with a SEO metadata table (title, slug, meta description, category, publish date, main image file name and alt). Article drafts can be written by Gemini from a topic and keywords. Articles already published in Sanity are also read in: the Blog page syncs them automatically when opened (and through the **Sync from Sanity** button), reading the public dataset without a token. Such articles appear as Published with their content converted to Markdown; their address cannot be changed, and when re-sent the same document is updated in place (author, categories, and other fields stay intact, and the existing image is reused). Articles deleted from the Studio no longer appear in the next sync.

Long pages use **tabs** to reduce scrolling: Connections & publishing (Instagram, YouTube, Blog, Publishing), AI settings (Brand, AI connection), Team account (My account, Team members), and the article editor (Details & image, Article body, Schedule & publish). The save button is always visible below the tabs.

**Importing articles.** Drop the `.zip` of an article package (for example `Vayora-Artikel-Blog.zip`) or its unpacked folder onto **Import content**; zip files are read in the browser, no unpacking needed. Each `.md` article with an SEO metadata table becomes a blog article (title, slug, summary, category, publish date, hero image file name, alt text and image prompt). Past publish dates are moved to the next free slot.

**Main image.** Upload an image (drag & drop), or write/keep an image prompt and press **Generate with AI**. The image provider is chosen in AI settings: **Gemini** (default, `gemini-2.5-flash-image`, about US$0.04 per image, one key for text and images) or **OpenAI** (`gpt-image-2`, 1536x1024, medium quality); both model names can be changed. The result is cropped to 16:9 and stored like an uploaded image. On import, articles with a prompt but no image can get their image generated automatically (one request each, shared daily limit set in AI settings, default 30); such articles are submitted for review instead of being scheduled so a person sees the picture first.

**Article list.** Filter by All, Draft, In review, Scheduled, Published or Failed (with counts) and search by title, slug or ID. Tick articles (or Select all) to act on several at once. **Schedule** (calendar icon on a row, or Schedule… for a selection) opens a planner like the Instagram/YouTube one: start date, publish days, times (WIB), a free slot for each article that skips times other articles use, editable per row, one approval, applied article by article with a result per row. In the editor, **Suggest the next free time** fills the next Monday/Wednesday/Friday 07:00 slot. Scheduled and failed articles also appear in **Queue**.

**Deleting.** The trash icon (kept apart from Open) or the one in the selection bar asks twice before it removes the article from Studio only; the Sanity document and the live page stay, and a synced article is not brought back by the next sync. Images inside the article body are not supported yet (the blog schema only holds text blocks).

## Content assistant and design

**Caption assistant with Gemini:** AI mode turns on automatically when a Gemini key is stored. Gemini **watches the whole video** (images, on-screen text, and narration); videos up to about 14 MB are sent directly, larger ones go through the Gemini Files API (stored by Google for at most 48 hours). For Shorts, the **YouTube** channel is selected automatically and produces three title + description + hashtag suggestions and a list of **YouTube Tags** (the **Use title** and **Use tags** buttons; tags are saved with the content and sent on upload). The AI imitates the **team style** from at most three of the latest content items that are scheduled, approved, or published on the same platform (structure, closing lines, AI illustration notes), without copying their content. The same applies to the automatic title & caption in **Create post**. In **Import content**, empty captions can be written by AI; that content is submitted for review, not scheduled directly.

The features are available through separate menus: **Caption assistant** to start from content, **Content design** for image posts with the real logo, **Brand knowledge** as the AI reference, **AI settings** for connections/limits/writing direction, and **Content strategy** for campaign guidance. From the editor there are three caption/hashtag options, an editorial check, and three test posting times in WIB. Local assistance and the design builder can be used right away; the mode that actually reads images and creates AI backgrounds requires an OpenAI API key/credit.

Assistant results are compared before being applied, can be undone, and are not saved or published automatically. Saved version history can be restored as a draft. Timing suggestions remain hypotheses until comparable performance observations are sufficient. The guide, the limits of Reel/carousel analysis, key settings, and the next marketing priorities are in [docs/ASISTEN-KONTEN.md](docs/ASISTEN-KONTEN.md).

The brand knowledge base contains 57 notes, 14 sources, and 24 campaign references (the knowledge content itself is in Indonesian). Search topics or filter by status through Brand knowledge; caption results show the context notes given to the assistant. Simulated prices, placeholders, and coming-soon features are kept separate from claims that may be used. Full summary: [docs/PENGETAHUAN-BRAND-VAYORA.md](docs/PENGETAHUAN-BRAND-VAYORA.md).

## Instagram connection

Live publishing is off by default and the queue is paused. You can still use login, the library, checks, and the calendar. No demo Instagram account is shown as a connected account.

The quickest way: open **Settings → Connections & publishing**, then paste the access token from the **Generate token** button in the Meta dashboard (Instagram → API setup; both Unified login `EAA…` and Instagram login `IGAA…` tokens are supported). This does not require an App ID, App Secret, or redirect URI; the Studio stores the token encrypted and renews it automatically. Meta login with an App ID and App Secret is still available as an advanced option. Full steps are in the [Instagram guide](docs/INSTAGRAM.md). Never enter your Instagram password in the Social Studio form.

## YouTube Shorts

A Short is its own content format: one vertical MP4 video up to 3 minutes, with the content title as the YouTube title and the caption as the description. Choose *YouTube Short* as the video destination when importing (`S01-…` files are detected automatically), connect the channel in **Settings → Connections & publishing → YouTube Shorts** with the Client ID/Secret from Google Cloud, then schedule it like any other content. Until the Google project passes the YouTube API audit, uploaded videos stay locked as private by YouTube. Full steps and API: [YouTube guide](docs/YOUTUBE.md).

## Team invitations

The owner can create editor invitations from Team account. The link is valid for 48 hours and can be used only once; send the link yourself. Editors cannot change Meta secrets or turn on live publishing. Changing the password is available from Team account and signs out other sessions.

## Data and backup

All data lives in the `data/` folder: the SQLite database, media, and `.encryption-key`. Back up the entire folder while the server is stopped. The encryption key must be included in the backup so Meta connections can be restored. Do not upload the data folder or `.env` to Git or share them.

`Hentikan-Vayora.ps1` only stops processes started by this launcher that match the project location. A process opened from a terminal can be stopped with Ctrl+C in that terminal.

## Testing

`npm test` runs tests for access, sessions, CSRF, invitations, approval, revision conflicts, OAuth state, and duplicate-publish prevention. The fake Meta transport exists only in tests. Test data is separate from the user's accounts and library.

The PRD is in [docs/PRD.md](docs/PRD.md).

## When deployed online

A Linux Docker package, HTTPS configuration, and a data migration script are available. Follow the [deployment guide](docs/DEPLOYMENT.md). The source package is built with `scripts/package-deployment.ps1`; account/media/key data is moved separately and privately. The production server refuses to run without a migrated owner account.

Use a VPS/server with Node 24+, an HTTPS reverse proxy, a persistent data volume, and a process manager so the app stays up 24 hours. Set `APP_ORIGIN=https://your-domain`, `PUBLIC_BASE_URL=https://your-domain`, and the matching hosts through `.env`. Restart the server, then open the app through that HTTPS address before connecting Instagram, so the OAuth session uses the same domain. Protect backups and restrict network access as the team requires.

The local version stops publishing when the computer sleeps or the server process stops. Schedules that are more than five minutes overdue are not published all at once after the app comes back up.

Structure documentation, UI migration limits, and Next.js verification: [MIGRASI-NEXTJS.md](docs/MIGRASI-NEXTJS.md).
